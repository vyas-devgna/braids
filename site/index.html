Why Braids

Line count is a bad measure of risk.

A one-line rename is usually harmless. A one-line authentication shortcut can become an incident. Braids looks at consequences, not diff size.

auth.py · “simplify token check”
- if not token or not expected: return False
- return secrets.compare_digest(token, expected)
+ return token == expected
Bug

Two missing values now authenticate because None == None.

Risk

A normal equality check can leak information through response timing.

Decision

Do not merge. Restore the guard and constant-time comparison.

How it works

Enough care for the consequence.

Braids adds only the work that can change the outcome. It can also decide that the right answer is no change.

01

Understand the surface

Find callers, constraints, trust boundaries, and failure paths before touching code.

02

Match effort to risk

Routine work stays direct. Risky work gets deeper treatment.

03

Prove what matters

Tests and measurements must match the claim being made.
